# Бизнес-модель и компоновка LIV Planning — 22.10.2026

## Рабочая модель

Объект и подрядчик — общий контекст работы, а не отдельные несвязанные списки. Договор связывает стороны и обязательства; один договор может охватывать несколько объектов. Один объект может иметь нескольких подрядчиков. Поэтому модель не сводится к жёсткому дереву из названий.

Единица производственного учёта — конкретный фронт: место + работа + исполнитель. Задача версии графика связывается с фронтом. В этой связи доступны объёмы, показатели, факт, ресурсы, схемы и обязательства. Версия графика хранит своё плановое основание; журнал хранит фактическую историю. При изменении рабочего прогноза договорные сроки не переписываются.

Общие разрезы: объект → подрядчик → договор → работа, плюс период и версия. Отбор допускает несколько значений. Неизвестная связь не считается совпадением. Названия сопоставляются со справочниками только однозначно; одинаковые номера договоров разных подрядчиков различаются. Для записи с недостающим объектом/договором используются явные связи с работами. Противоречащий явный объект не подменяется догадкой.

## Что показали предоставленные примеры

Локально изучены структуры доступных книг сетей, графиков кровли/фасадов и договорного приложения по паркингу; визуально просмотрены табличный отчёт и ресурсная временная схема, прочитана структура справки КД. Реальные значения и файлы не импортировались и не публикуются в составе примеров приложения. Четыре формы монолита учитывались по ранее данному описанию пользователя; не заявляется повторное чтение отсутствующих отдельных исходников.

- Сети требуют выбора измеряемого показателя, месяца/недели, участка и сопоставления плана, факта и отклонения. Метры трубы, метры траншеи и штуки колодцев не являются одним объёмом.
- Договорные приложения разделяют работы, элементы, захватки, длительности и даты. Эти поля сохраняются отдельно.
- Ресурсная схема показывает занятость конкретных единиц во времени. Пиковые значения разных работ нельзя просто складывать в общий пик.
- Табличный отчёт по работам и справка КД отвечают на разные вопросы: физическое выполнение, статус, план/факт дат; отдельно — обязательство, редакция, исключения и документальное подтверждение.
- Пользовательские месячные и недельные формы должны быть представлениями общей базы, а не самостоятельными копиями факта.

## Назначение экранов

| Экран | Основная задача | Связанные действия |
|---|---|---|
| График | Состав, последовательность, план и версии | Периодный план, назначения, договорные графики, связи КД |
| План / факт | Сравнение одних работ за выбранный период | Объёмы / люди / техника / совместный вид; переход по работе |
| Факт | Ежедневный ввод и исправления | Люди, техника, объёмы, выбор фронта, просмотр связанной схемы |
| Прогноз | Состав → срок и срок → потребность | Условия, сценарии, полная сеть, принятие рабочей версии |
| Гант | Временная картина и совместная загрузка | Зависимости, выравнивание, переносы и влияние на КД |
| Объёмы | Состав и действующие количества | Изменения, согласование, история, факт и остаток |
| Ключевые даты | Обязательства сторон | Договор, объект, подрядчик, связанные работы, факт подтверждения |
| Ресурсы | Общий журнал и анализ численности | Нераспределённые записи организации, доступность, планы |
| Схемы | Пространственная привязка | Отметки, фронты, элементы, готовность из общего факта |
| Шахматка | Настраиваемое табличное представление | Разрезы места и работ, показатели, статусы |
| Отчёты | Выпуск формы для выбранной аудитории | Общий контекст фиксируется в неизменном снимке |

Справочники и обслуживание сгруппированы отдельно от основных производственных вкладок. Существующие разделы доступны; исходные данные не удаляются из-за переноса интерфейса.

## Поток данных

Объёмы + выбранная версия графика → план по периодам.

Журналы выполнения и ресурсов → фактические периоды.

План + факт → сравнение и отклонение.

Действующий остаток + производительность + будущие ресурсы + календари/связи → прогноз → проверка договорных сроков и КД.

Схема представляет связанные работы и элементы. Рисунок сам по себе не создаёт выполненный объём. Физическое выполнение само по себе не подтверждает освидетельствование или закрытие КД.

## План / факт

Основной экран — одна таблица сравнения. Показатели переключаются: объёмы, люди, техника, объёмы + люди. Сохраняются работы, объект, подрядчик, договор и период. Период можно разложить по дням, неделям или месяцам. Доступны сохраняемые виды и выгрузка всей таблицы, а не только видимой страницы.

Ручные предположения прогноза не меняют назначения сохранённой версии в сравнении. Если численность не задана в выбранном графике, допустим явно привязанный ручной план ресурсов; источник подписан. Пересекающиеся ручные планы не складываются молча.

Объёмы сравниваются отдельно по единицам. Для дополнительных показателей фронта выбираются собственные факты и количества. План дополнительного показателя показывается только при наличии отдельной подневной записи либо явно заданного количества этого показателя в графике. Пропорция от основного показателя не придумывается.

Средняя численность, максимум и ресурсодни различаются. Итог максимума строится по одновременной дневной загрузке; недельные пики и средние не складываются в месячный итог. Отсутствующий отчёт не превращается в нулевой. При неполной истории показано покрытие и недоступно полное сравнение. Нулевое значение, записанное явно, сохраняет смысл известного нуля.

Численность организации без фронта не переносится автоматически на её работы. Такие записи показаны отдельным раскрываемым списком. Повторный ввод того же состава по фронту блокируется, пока исходная нераспределённая запись не разнесена в журнале; это предотвращает очевидное двойное суммирование. Для точного учёта уникальных физических лиц нужны персональные идентификаторы; текущая модель считает численность назначений, не уникальных людей.

Связь работы с выбранным фронтом сохраняется вместе с ежедневным отчётом. Объект и известный подрядчик проверяются до записи. Ключ ведомости объёмов сохраняется при привязке. До создания графика существующие фронты доступны для сравнения подневного плана/факта и ежедневного ввода.

## Критерии удобства и проверки

- Выбрать объект и подрядчика один раз; перейти к объёмам, КД, Ганту и обратно без потери отбора.
- Из сравнения выбрать работу и открыть её факт, прогноз или схему без повторного поиска.
- Переключить объёмы на людей и сохранить выбранный период/основание.
- Понимать источник каждого плана и причины отсутствующих значений.
- Различать отклонение за неделю и риск конечной даты.
- Получать корректные итоги и читаемые заголовки; конструктор колонок хранит разные настройки для разных показателей.
- Сохранить вид и восстановить объект, подрядчика, договор, период и показатель.
- Сохранить связь и факт, затем восстановить их в новой сессии.

Проверки выполняются на искусственных данных и DOM. Рабочие файлы не импортировались; схема БД и реальные серверные записи не изменялись. Визуальная приёмка заполненного авторизованного приложения и полного серверного цикла остаётся отдельной проверкой. Моделирование физических фронтов/технологической совместимости и полноценное совместное редактирование не объявляются завершёнными этим выпуском.

Итог проверки выпуска: 167 локальных тестов, 164 успешно, 3 существующие проверки XLSX пропущены. Проверены синтаксис всех JS-модулей и ссылки на локальные скрипты. Отдельно покрыты холодный запуск, поздняя загрузка схем после группировки навигации, сохранение вида, восстановление связи работы с фронтом, отдельные показатели сетей, общие фильтры и корректный одновременный пик ресурсов.
