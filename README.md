# ACONS Planning v4

Рабочая промежуточная версия системы планирования и контроля строительства.

## Что уже можно делать

### Основные здания

Можно:

- вести шахматку;
- фильтровать по зданию;
- фильтровать по блоку;
- фильтровать по этажу;
- фильтровать по стороне;
- фильтровать по статусу;
- хранить договорные даты;
- хранить базовые даты;
- хранить рабочие даты;
- хранить фактические даты;
- хранить прогноз окончания;
- хранить объемы;
- хранить текущую численность;
- хранить подрядчика;
- хранить ответственного;
- отмечать физическое выполнение;
- отмечать предъявление;
- отмечать сдачу / приемку;
- хранить дату сдачи;
- хранить ограничения;
- хранить комментарии.

## Структура

Во вкладке «Настройки» можно:

- добавлять здания;
- добавлять виды работ;
- создавать новые блоки;
- создавать новые зоны;
- создавать этажи;
- создавать оси;
- создавать стороны;
- создавать все виды работ сразу;
- создавать один выбранный вид работ.

Данные сохраняются в браузере.

## Журнал плана

Для каждого фронта можно по любой дате записывать:

- плановый объем;
- плановую численность;
- комментарий.

Записи не перезаписывают друг друга.

Это нужно для аналитики по любым интервалам.

## Журнал факта

Для каждого фронта можно по любой дате записывать:

- фактический объем;
- накопительный объем;
- фактическую численность;
- статус;
- комментарий.

Записи не перезаписывают друг друга.

## Аналитика

Можно выбрать два произвольных периода и сравнить:

- плановый объем;
- фактический объем;
- отклонение;
- плановую численность;
- фактическую численность;
- отклонение численности;
- плановые старты;
- фактические старты;
- плановые окончания;
- фактические окончания;
- количество сданных работ.

Можно сравнивать:

- неделю с неделей;
- месяц с месяцем;
- любой произвольный интервал;
- план с фактом;
- людей план / факт;
- объемы план / факт.

## Демонтаж

Для объектов демонтажа можно вести:

- статус;
- договорное начало;
- договорное окончание;
- рабочее начало;
- рабочее окончание;
- фактическое начало;
- фактическое окончание;
- прогноз окончания;
- предшественника;
- тип связи;
- лаг;
- предъявление;
- сдачу;
- дату сдачи;
- комментарии;
- ограничения;
- отклонение от договорного окончания.

## Как начать работать

1. Открой вкладку «Настройки».
2. Проверь список зданий.
3. Проверь список работ.
4. Добавь нужные разбивки.
5. Перейди во вкладку «Основные здания».
6. Нажми на нужную ячейку шахматки.
7. Заполни карточку фронта.
8. Через «Журнал плана» заполняй план по датам.
9. Через «Журнал факта» фиксируй факт.
10. Во вкладке «Аналитика» выбирай любые два интервала.

## К чему идем

Цель — единая система планирования и контроля строительства.

Одна работа должна иметь несколько представлений:

- шахматка;
- график;
- план / факт;
- объемы;
- люди;
- сдача;
- ограничения;
- история изменений.

## Уровни структуры

Основная логика:

Здание  
→ Блок  
→ Этаж  
→ Ось / сторона / зона / захватка  
→ Вид работ

При этом уровни должны быть необязательными.

Например:

ДЭС  
→ Кровля

или:

Главный корпус  
→ Блок 2  
→ 6 этаж  
→ А / море  
→ Штукатурка

## Даты

Для каждой работы планируем хранить:

- договорное начало;
- договорное окончание;
- базовое начало;
- базовое окончание;
- рабочее начало;
- рабочее окончание;
- фактическое начало;
- фактическое окончание;
- прогноз окончания.

## Объемы

Объемы должны быть необязательными.

Если объемы есть:

- общий объем;
- единица измерения;
- плановый объем;
- фактический объем;
- накопительный объем;
- остаток;
- процент выполнения.

Если объемов нет — работа продолжает нормально существовать по статусу и датам.

## Люди

Для каждой работы планируется хранить:

- плановую численность;
- фактическую численность;
- человеко-дни;
- динамику численности;
- отклонение план / факт;
- производительность.

## Сдача

Отдельно должны храниться:

- физически выполнено;
- предъявлено;
- сдано / принято;
- дата сдачи.

Физически завершенная работа и сданная работа — не одно и то же.

## График

Планируется полноценный Гант.

Отдельные представления:

- договорный;
- базовый;
- рабочий;
- фактический;
- прогнозный.

Связи:

- окончание → начало;
- начало → начало;
- окончание → окончание;
- начало → окончание.

Также:

- лаги;
- календари;
- рабочие дни;
- автоматический пересчет;
- возможность отключить автоматический пересчет;
- ключевые даты.

## Пользователи

Планируемые роли:

### Администратор

Полный доступ.

### Планировщик

Доступ к:

- графикам;
- плану;
- факту;
- датам;
- аналитике;
- структуре.

### Ответственный

Доступ к:

- факту;
- людям;
- статусам;
- ограничениям;
- своим фронтам.

### Подрядчик

Доступ только к своим работам.

Не может менять договорные даты.

### Заказчик

Только просмотр разрешенных данных.

Можно отдельно ограничивать:

- внутренние комментарии;
- людей;
- служебные поля;
- отдельные здания;
- отдельные разделы.

Для заказчика планируется отдельный чистый режим:

- сводка;
- план / факт;
- ключевые даты;
- прогресс;
- Гант;
- сдача.

## История изменений

Система должна хранить:

- кто изменил;
- когда изменил;
- какое поле;
- старое значение;
- новое значение.

Например:

05.10.2026 14:35  
Рабочее окончание:  
12.10.2026 → 18.10.2026

## Ограничение текущей версии

Пока данные хранятся только в браузере конкретного пользователя.

Это значит:

- данные не общие между пользователями;
- другой компьютер их не увидит;
- права доступа пока только описаны;
- многопользовательской работы пока нет.

Для нормальной рабочей эксплуатации нужна общая база данных и вход пользователей.
