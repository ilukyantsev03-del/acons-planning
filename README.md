# ACONS Planning v3 — как пользоваться

## Что уже работает в этой версии
- Основные здания и шахматка.
- Отдельные колонки: здание, блок, этаж, ось/сторона.
- Можно добавлять новые здания.
- Можно добавлять новые виды работ.
- Можно добавлять новые разбивки: блок/зона, этаж, ось/сторона.
- Новая разбивка сохраняется и автоматически создает выбранные виды работ.
- Отрицательные этажи можно хранить, но в фасадной шахматке они не показываются.
- Фронт хранит статусы, факт, людей, ограничения, договорные/рабочие/фактические даты, объемы, предъявление и сдачу.
- Журнал факта хранит записи по датам.
- Аналитика сравнивает любые два интервала по факту объемов, человеко-дням, стартам, окончаниям и сдаче.
- Демонтажные объекты имеют договорные/рабочие/фактические даты, связи и сдачу.
- Все данные сейчас сохраняются в браузере через localStorage.
- Есть экспорт/импорт JSON резервной копии.

## Как добавлять новое здание
1. Открой вкладку **Настройки**.
2. В блоке **Здания** введи название.
3. Нажми **Добавить**.
4. Затем ниже в блоке **Структура здания / новая разбивка** выбери новое здание.
5. Укажи блок/зону, этаж и ось/сторону.
6. Выбери: создать все виды работ или один конкретный.
7. Нажми **Добавить разбивку**.

## Как добавлять новый вид работ
1. Вкладка **Настройки**.
2. Блок **Виды работ**.
3. Введи название и нажми **Добавить**.
4. Для существующей или новой разбивки через блок ниже создай этот вид работ.

## Как вести ежедневный/еженедельный факт
1. Открой нужную ячейку шахматки.
2. Сохрани текущие данные карточки.
3. Нажми **Добавить запись факта**.
4. Укажи дату, выполненный объем за период, накопительный объем, людей и комментарий.
5. Каждая запись остается в журнале и попадает в аналитику.

## Как сравнивать периоды
1. Открой **Аналитика**.
2. Укажи Период A и Период B.
3. Выбери здание, вид работ, блок или этаж.
4. Нажми **Сравнить**.
5. Система покажет:
   - факт объема по каждому периоду;
   - человеко-дни;
   - плановые и фактические старты;
   - плановые и фактические окончания;
   - количество сданных работ;
   - разницу между периодами.

## Что значит человеко-дни
Если 10 человек работали один день — это 10 человеко-дней.
Если 10 человек работали 5 дней и каждый день есть запись — это 50 человеко-дней.
Поэтому для точной аналитики людей лучше делать записи по дням или по каждому отчетному срезу.

## Текущий доступ
GitHub Pages — публичный сайт. Сейчас:
- любой, у кого есть ссылка, может открыть сайт;
- данные хранятся только в браузере конкретного пользователя;
- данные разных пользователей не синхронизируются;
- это пилот и не подходит для конфиденциальной эксплуатации.

## Как сделать нормальный доступ для нас и заказчика
Нужно подключить Supabase и авторизацию.

### Роли
- **Администратор** — всё.
- **Планировщик** — графики, шахматки, аналитика, договорные и рабочие даты.
- **Ответственный** — факт, люди, статусы, ограничения по своим фронтам.
- **Подрядчик** — только свои фронты, без права менять договорные даты.
- **Заказчик** — только просмотр разрешенных объектов и отчетов.

### Ограничение по зданиям
Для каждого пользователя создается scope:
- Главное здание — читать/редактировать;
- Паркинг — только читать;
- другие здания — нет доступа.

### Для заказчика
Лучший вариант:
- отдельная учетная запись;
- роль `customer`;
- только `SELECT`;
- отдельный набор разрешенных зданий;
- можно скрыть внутренние комментарии, людей и служебные поля;
- показать только согласованный Dashboard / план-факт / ключевые даты.

## Что нужно дальше для реальной общей базы
1. Создать Supabase project.
2. Выполнить `supabase-schema.sql` в SQL Editor.
3. Включить Email Auth.
4. Создать первого пользователя-admin.
5. Настроить RLS-политики.
6. Заменить localStorage в приложении на Supabase API.
7. После этого данные будут общими для всех пользователей и доступ будет управляться ролями.
