Осталось: авторизованный цикл загрузки/рисования/сохранения/перезагрузки PDF, завершение синхронизации в той же сессии, предпросмотр 2–3 строк рабочего файла КД. Доступный агенту браузер открывает форму входа; файл рабочих КД для этой проверки не предоставлен. Административный SQL-тест не заменяет браузерную проверку прав пользователя.

## Правило

До завершения этого сценария не выполнять массовую загрузку рабочих данных.

project_snapshot остаётся страховочным источником чтения. Нормализованная Supabase-модель работает параллельно. Переключение чтения на сервер выполняется только после успешного тестового цикла.

## 1. Запуск

1. Открыть LIV.
2. Выполнить Ctrl+F5.
3. Дождаться статуса «Серверная база синхронизирована».
4. Нажать кнопку «Проверка».
5. В ручной проверке не должно быть отсутствующих локальных ID на сервере.

## 2. PDF

1. Открыть «Схемы».
2. Загрузить PDF с кириллическим именем, например «Кровля_08.10.26.pdf».
3. Убедиться, что загрузка проходит без Invalid key.
4. Открыть несколько страниц PDF.
5. Создать отметку.
6. В карточке отметки не должно быть ручного поля процента.
7. Связать отметку с фронтом: процент должен рассчитываться только из фактического и общего объёма.
8. Удалить тестовую схему и убедиться, что исходный PDF удаляется из Storage.

## 3. Ключевые даты

1. Открыть специализированный импорт КД.
2. Загрузить тестовую книгу из нескольких листов.
3. Выбрать «Все листы».
4. Проверить распознавание подрядчика, номера договора, наименования КД и даты окончания.
5. Для одного нестандартного листа перейти на него отдельно и исправить сопоставление колонок.
6. Вернуться в «Все листы»: ручное сопоставление должно сохраниться.
7. Проверить предпросмотр.
8. Импортировать сначала 2–3 строки.
9. Проверить карточки КД и договоры.
10. Повторно загрузить тот же файл: существующие КД должны определяться как обновление, а не как новые дубли.
11. Проверить распознавание цели из текста, например «190 свай» → 190 шт.

## 4. Прогноз риска КД

1. Связать КД с фронтом, группой свай/анкеров либо конкретным показателем объёма.
2. Указать целевой объём, если он не распознан автоматически.
3. Проверить окно фактического темпа и календарь 7/0, 6/1 или 5/2.
4. Добавить несколько тестовых фактов.
5. Проверить:
   - факт;
   - остаток;
   - фактический темп;
   - требуемый темп;
   - прогнозный объём;
   - прогнозный недобор;
   - прогнозную дату завершения;
   - уровень риска.

## 5. Рабочий график

1. Загрузить тестовый график в тестовый контур.
2. Проверить ID задач и WBS/структурные номера.
3. Проверить базовые и текущие даты.
4. Проверить связи FS/SS/FF/SF и лаги.
5. До принятия посмотреть сравнение:
   - новые;
   - изменённые;
   - без изменений;
   - отсутствующие;
   - количество зависимостей.
6. Только после проверки нажать «Принять как рабочий график».
7. Убедиться, что предыдущая версия осталась в истории.

## 6. Фронт и несколько показателей

Создать один тестовый фронт наружной или внутренней сети.

Пример:
- основной объём — участок сети;
- труба, м.п.;
- траншея, м;
- обратная засыпка, м;
- колодцы, шт.

Проверить сохранение и повторное открытие карточки.

## 7. Факт

Проверить отдельно:

### Дневной факт
- показатель «Труба»;
- дата;
- +10 м.п.

### Накопительный снимок
- тот же показатель;
- дата;
- накопительно 50 м.п.

Убедиться:
- cumulative_snapshot не суммируется как ещё один дневной факт;
- факты разных показателей одного фронта не смешиваются;
- общий План/факт использует только основной показатель фронта;
- импорт факта обновляет состояние фронта только для основного показателя.

## 8. Номерные элементы

Создать:
- Г1 №7;
- Г2 №7.

Обе записи должны сохраниться.

Повторно создать Г1 №7 — система должна определить дубль.

Проверить тот же сценарий импортом свай/анкеров.

## 9. Ресурсы

1. Открыть существующие ресурсы.
2. Проверить текущую дату.
3. Проверить ИТР / Рабочие / Механизаторы.
4. Проверить технику.
5. Проверить методы Среднее / Максимум / Последнее / Скользящее.
6. Убедиться, что исходные 19 844 строк не потеряны.

## 10. Отчётный снимок

1. Нажать «Зафиксировать отчёт».
2. Указать отчётную дату и предыдущую отчётную дату.
3. Сохранить.
4. В снимок должны войти:
   - фильтры;
   - фронты;
   - основные и дополнительные показатели;
   - недельный прирост;
   - ключевые даты;
   - номерные элементы.
5. Повтор с тем же типом, датой и названием должен быть заблокирован.

## 11. Конфликт редактирования

После подключения второго тестового пользователя:
1. открыть одну запись в двух сессиях;
2. изменить и сохранить в первой;
3. попытаться сохранить старую версию во второй;
4. LIV должен показать конфликт, а не перезаписать серверную запись.

## 12. После успешного теста

Только после прохождения пунктов выше:
1. начать перевод чтения разделов с project_snapshot на нормализованные таблицы;
2. переводить по одному разделу;
3. snapshot оставить резервным экспортом/восстановлением;
4. после стабильного периода отключить его от обычного рабочего чтения.

## Проверка исправлений 14.10: формы PDF и запуск синхронизации

- После Ctrl+F5 выбрать точку, линию, круг и прямоугольник в панели схемы. Точка ставится щелчком, остальные формы — протягиванием. Сохранить карточку, проверить масштабирование и повторную загрузку.
- Проверить горизонтальную, вертикальную и обратную диагональную линию.
- После входа дождаться загрузки проекта; сверка ID не должна отправлять пустой UUID.
- Автоматически проверены 17 регрессий и запись трёх форм в транзакции Supabase с откатом. Проверка в авторизованном браузере остаётся обязательной.

## Редактор схем: свободное рисование (14.10, новая версия)

Предыдущая инструкция об автоматическом открытии карточки после каждой фигуры больше не применяется.

- Выбрать форму, цвет (свой либо по статусу), толщину 1–20 пкс и заливку. Нарисовать несколько фигур подряд: карточки не открываются.
- Нажать «Сохранить рисунки». До успешного сохранения видны счётчик и предупреждение о несохранённых изменениях; при закрытии страницы браузер предупреждает.
- «Завершить рисование» или Esc; щелчком выбрать отметку и изменить оформление на панели. Сохранить изменения.
- «Данные отметки» или двойной щелчок открывает карточку со связями и статусом.
- Проверить сохранение цветов и толщин после перезагрузки, удаление новой и сохранённой отметки, повтор сохранения после ошибки сети.
- Автоматические тесты покрывают серию рисунков, отсутствие карточки при отпускании мыши, сохранение оформления и сохранность черновиков при ошибке. Визуальная проверка браузером в этой среде недоступна.
